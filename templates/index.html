connecting to redis

session-backed visit counter

Every visitor gets one count.
Redis makes sure of it.

A small API that tracks unique sessions with TTL-based expiry, so refreshes don't inflate your numbers and idle visitors quietly drop off.

Endpoints

Everything the counter exposes

GET /hit/<key>

Registers a visit for the current session and returns the running total. A new session is claimed atomically and expires after the configured TTL.

GET /status

Reports Redis health — uptime, memory use, throughput — for keeping an eye on the store behind the counter.

GET /health

A plain liveness check. Returns healthy once the API can reach Redis, unhealthy otherwise.

GET / POST /data/<key>

General-purpose key/value storage, separate from the counter's own keyspace.
